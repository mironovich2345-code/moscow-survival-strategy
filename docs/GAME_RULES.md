# Game Rules

Числовые правила. Все константы живут в коде (`src/game/**`) — при изменении
правила обновлять и этот файл, и тесты.

## Время

| Правило | Значение | Константа |
|---|---|---|
| Длительность хода | 2 игровых часа | `HOURS_PER_TURN` (`src/game/time`) |
| Старт кампании | День 10, 08:00 | `CAMPAIGN_START_DAY`, `CAMPAIGN_START_HOUR` |

Время хранится как абсолютный час с момента катастрофы (день 1, 00:00).

## Группа

| Правило | Значение | Константа |
|---|---|---|
| Максимальный размер группы | 12 | `MAX_GROUP_SIZE` (`src/game/characters`) |
| Максимальный боевой отряд | 5 | `MAX_SQUAD_SIZE` (`src/game/expeditions`) |
| Герой | ровно 1 на кампанию | проверяется в `createNewGame` |

## Ресурсы

`food`, `water`, `medicine`, `ammunition`, `fuel`, `materials`.
Целые неотрицательные числа; запас не может опуститься ниже 0.

Стартовые запасы прототипа (`src/data/content.ts`): food 20, water 20,
medicine 2, ammunition 24, fuel 10, materials 15.

## Персонажи

- Характеристики: strength, agility, endurance, perception, intelligence.
- Навыки: firearms, melee, medicine, scavenging, stealth.
- Экипировка: слоты `sidearm`, `primary`, `melee`, `body`, `backpack`
  (см. «Склад и экипировка»).
- Состояние (`condition`): health / maxHealth, `hungry`, `thirsty`;
  назначение (`base` / `expedition`).
- В отряд можно взять персонажа, который на базе и жив (health > 0).

Из навыков в 0.2 на результат влияет только **scavenging** (см. «Добыча»).
Остальные навыки и характеристики — задел.

## Склад и экипировка

**Склад базы** состоит из двух частей:
- **уникальные предметы** (`GameState.storage.items`) — экземпляры со стабильным ID;
- **ресурсы базы** (`GameState.resources`): расходники `food`, `water`,
  `medicine`, `ammunition` и обычные числовые `fuel`, `materials`.

`ammunition` — универсальный ресурс, калибров нет.

**Уникальный предмет** — экземпляр (`ItemInstance { id, defId }`) в реестре
`GameState.items`. Каждый экземпляр **всегда находится ровно в одном месте**:
- на складе (`storage.items`), **или**
- в одном слоте одного персонажа (`character.equipment[slot]`), **или**
- в найденном грузе активной экспедиции (`expedition.haulItems`), **или**
- среди вещей павших в активной экспедиции (`expedition.lostItems`), **или**
- потерян в мире (`GameState.lostItems` — лежит в локации, где его бросили).

Персонаж в экспедиции несёт свою экипировку — это его слоты, не груз экспедиции.
Логика проверяет инвариант (`findItemLocationErrors`) при новой игре, в тестах
и при загрузке; сейв, который его нарушает, не загружается.

**ID экземпляра** стабилен на всё время игры:
- стартовые предметы — `<defId>-1` (например `pm_pistol-1`);
- найденные — `<defId>-<n>`, где `n` — глобальный счётчик `GameState.nextId`
  в момент находки (например `pump_shotgun-17`). ID выдаётся **только**
  предмету, который отряд смог взять; при переходе в склад и при
  сохранении/загрузке ID не меняется.

**Слоты:** `sidearm`, `primary`, `melee`, `body`, `backpack`. Предмет можно
надеть только в слот своего типа.

**Перемещение предмета** (команда `moveItem`) — одна операция для всех случаев:

| Откуда → куда | Смысл |
|---|---|
| склад → персонаж | экипировать со склада |
| персонаж → склад | снять |
| персонаж → другой персонаж | передать |

- Оба участника (кто отдаёт и кто получает) должны быть **на базе** и живы.
  Предметы персонажа в экспедиции недоступны.
- Если слот получателя занят — прежний предмет **уходит на склад**.
- Предметы в грузе экспедиции (`haulItems`) недоступны, пока отряд не вернулся.

Стартовые предметы: ПМ (герой, sidearm), рабочая куртка (герой, body),
пожарный топор (Максим, melee), туристический рюкзак (Максим, backpack).

## Вес и грузоподъёмность

Все веса — целые условные единицы.

| Что | Вес |
|---|---|
| Уникальный предмет | вес из каталога (см. выше) |
| food, water, medicine, fuel, materials | 1 за единицу |
| ammunition | 1 за каждые начатые 10 патронов: `ceil(n / 10)` |

Вес ресурсов считается по суммарному количеству каждого вида:
`resourceWeight = Σ ceil(amount_k / unitsPerWeight_k)`, где `unitsPerWeight`
= 10 для ammunition и 1 для остальных.

| Правило | Значение | Константа |
|---|---|---|
| Базовая грузоподъёмность персонажа | 10 | `BASE_CARRY_CAPACITY` (`src/game/inventory`) |
| Туристический рюкзак | +15 | `capacityBonus` предмета |
| Маленький городской рюкзак | +8 | `capacityBonus` предмета |

**Формулы:**
- `capacity(персонаж) = 10 + capacityBonus рюкзака` (без рюкзака — 10).
- `capacity(отряд) = Σ capacity(участник)`.
- `load(отряд) = Σ вес экипировки участников + Σ вес haulItems + resourceWeight(supplies + haul)`.
- Экипировка (включая сам рюкзак) **входит** в груз.

**Правила:**
- Отряд **нельзя отправить**, если стартовый `load > capacity` (ошибка `OVERLOADED`).
- Штрафов за перегруз нет.
- Любая находка (событие или добыча локации) добавляется **поштучно**, пока
  следующая единица помещается: `load + вес ≤ capacity`. Всё, что не
  поместилось, **остаётся на месте** (теряется для этой экспедиции) и
  записывается в журнал.
- Порядок заполнения: для добычи локации — сначала ресурсы в порядке таблицы
  `loot`, затем уникальные предметы в порядке таблицы `itemLoot`;
  для событий — food, water, medicine, ammunition, fuel, materials.
- **Уникальный предмет** берётся целиком, только если `load + вес предмета ≤
  capacity`. Иначе он не создаётся и не попадает в груз, а журнал пишет, что
  предмет пришлось оставить. Ради нового предмета **ничего из уже взятого
  не выбрасывается**.

## Подготовка и припасы экспедиции

- Перед отправкой игрок выбирает локацию, до 5 участников, меняет их
  экипировку (на базе, `moveItem`) и выбирает **припасы отряда**:
  food, water, medicine, ammunition (целые числа ≥ 0).
- Припасы **сразу списываются** с ресурсов базы и хранятся в
  `Expedition.supplies`. Взять больше, чем есть на базе, нельзя
  (`NOT_ENOUGH_SUPPLIES`).
- У экспедиции два «кармана»:
  - `supplies` — то, что взяли с базы;
  - найденный груз: `haul` — ресурсы (только неотрицательные), `haulItems` —
    ID найденных уникальных предметов.
- **Расход в пути** (события, суточный паёк) берётся сначала из `supplies`,
  а если их не хватает — из `haul` того же вида. Ниже 0 не уходит.
- **При возвращении** на склад поступает: остаток `supplies` + `haul` +
  добыча локации (с учётом вместимости); найденные уникальные предметы
  переходят в `storage.items` с тем же ID и дальше экипируются обычным
  `moveItem`. Экипировка остаётся на персонажах.
- Журнал фиксирует: что взяли (выход), что потратили (события, паёк),
  что нашли (события, добыча, что пришлось бросить), с чем вернулись.

## Еда и вода (суточный расход)

| Правило | Значение | Константа |
|---|---|---|
| Расход еды | 1 food на живого человека в сутки | `FOOD_PER_PERSON_PER_DAY` (`src/game/survival`) |
| Расход воды | 1 water на живого человека в сутки | `WATER_PER_PERSON_PER_DAY` |

- Расход происходит **один раз при переходе на новый день** — в тот ход,
  когда часы переходят через 00:00 (ход 22:00 → 00:00).
- Считается **отдельно для каждой группы**:
  - живые **на базе** едят и пьют с **ресурсов базы**;
  - живые участники **каждой экспедиции** — из **припасов этой экспедиции**
    (`supplies`, затем `haul`). Со склада базы дистанционно есть нельзя.
- Еда и вода считаются независимо друг от друга.
- **Хватает** (запас группы ≥ числа живых в группе): списывается ровно по 1
  на человека, у всех снимается `hungry` / `thirsty`.
- **Не хватает:** запас распределяется по одной порции **в порядке списка
  группы** (герой первый, дальше — в порядке присоединения). Запас становится 0
  (ниже 0 не уходит). Получившие порцию — флаг снимается, не получившие —
  `hungry = true` (для еды) / `thirsty = true` (для воды).
- Голод и жажда пока **не наносят урон и не убивают** — только статус.

## Добыча и навык поиска

Для каждой записи `loot` локации:

1. Если у записи есть `chance` (0–100 %) — сначала бросок `nextInt(1, 100)`;
   если результат > `chance`, эта позиция не выпала (0).
2. Базовое количество: `roll = nextInt(min, max)`.
3. Бонус поиска: `S` = **сумма** навыка scavenging всех участников отряда;
   `bonus% = min(10 × S, 100)`.
4. Итог: `floor(roll × (100 + bonus%) / 100)`.

Пример: Герой (2) + Максим (2) → S = 4 → +40 %. Бросок 5 → floor(5 × 1.4) = 7.

## Экспедиции

- Отряд: 1–5 уникальных доступных персонажей.
- Базовая длительность задаётся локацией (`expeditionTurns`).
- Отряд возвращается в конце хода, на котором `time >= returnsAt`.
- Припасы, находки и вместимость — см. «Подготовка и припасы экспедиции»
  и «Вес и грузоподъёмность».
- **Обыск локации** (0.3.1) происходит **в середине похода**, а не при
  возвращении: в конце хода, когда `time ≥ searchAt`, где
  `searchAt = время выхода + ceil(expeditionTurns / 2) ходов`
  (аптека и магазин — через 2 хода, парковка — через 2, полиция — через 3).
  Найденные ресурсы и предметы сразу попадают в `haul` / `haulItems` (с учётом
  вместимости) и видны в «Найдено» у активной экспедиции; дальше отряд
  несёт их домой. Если обыск и возвращение выпадают на один ход — сначала обыск.
- Эффект `delay` до обыска сдвигает и `searchAt`, и время возвращения.
- **Прерванная** экспедиция (`aborted`) возвращается в конце следующего хода.
  Если обыск ещё не был — добычи локации нет; если уже был — найденное
  остаётся в грузе и возвращается на склад.
- Риск локации (`low` / `medium` / `high`) в 0.2 **чисто информационный**.

### Локации Лефортово

| Локация | Время | Риск | Добыча (до бонуса поиска) |
|---|---|---|---|
| Аптека | 3 хода (6 ч) | низкий | medicine 1–5 |
| Продуктовый магазин | 3 хода (6 ч) | низкий | food 2–6, water 2–6 |
| Подземная парковка | 4 хода (8 ч) | средний | fuel 2–5, materials 2–6 |
| Отдел полиции | 5 ходов (10 ч) | высокий | ammunition 6–15, medicine 1–2 (шанс 25 %) |

**Уникальные предметы в добыче** (`itemLoot`): для каждой записи — бросок
`nextInt(1, 100) ≤ chance`, после броска ресурсов. Бонус поиска на шанс
предмета **не влияет**. Прерванная экспедиция предметы локации не получает.

| Локация | Предмет | Шанс |
|---|---|---|
| Подземная парковка | Маленький городской рюкзак | 15 % |
| Подземная парковка | Монтировка | 15 % |
| Отдел полиции | Помповый дробовик | 10 % |
| Отдел полиции | Полицейский бронежилет | 15 % |

## События экспедиции

| Правило | Значение | Константа |
|---|---|---|
| Шанс события | 25 % на экспедицию за ход | `EVENT_CHANCE_PERCENT` (`src/game/expeditions`) |

- В конце каждого хода, для каждой экспедиции, которая **не** вернулась
  в этот ход и не ждёт решения: бросок `nextInt(1, 100) ≤ 25`.
- Событие выбирается равновероятно из ещё не встреченных этой экспедицией
  (одно событие не повторяется в рамках одного похода). Если все встречены —
  событий больше нет.
- Событие ставит экспедицию на паузу (`pendingEventId`). Пока есть хотя бы одно
  нерешённое событие, **завершить ход нельзя** — игрок обязан выбрать решение.
- Выбор решения: у варианта один или несколько исходов с весами (`weight`);
  исход выбирается броском `nextInt(1, сумма весов)`. Один исход — без броска.
- У варианта может быть требование `requires` (например, 2 ammunition для
  «Застрелить»). Если у отряда (`supplies + haul`) этого нет — вариант
  **недоступен** (`CHOICE_UNAVAILABLE`). В каждом событии есть хотя бы один
  вариант без требований.
- Последствия (`effects`):
  - `resources` с **отрицательным** значением — немедленный расход из припасов
    экспедиции (`supplies`, затем `haul`; не ниже 0);
  - `resources` с **положительным** значением — находка в `haul`
    (с учётом вместимости, лишнее остаётся на месте);
  - `delay` — +N ходов к времени возвращения;
  - `abort` — экспедиция прерывается (см. выше).
- После выбора экспедиция продолжается с того же места.

### Тестовые события (0.2)

Шум в соседнем здании, Закрытая дверь, Следы другой группы, Один заражённый,
Брошенная сумка. Тексты и исходы — `src/data/events/events.ts`.

## Бой (Prototype 0.4)

Только **заражённые**. Бой — отдельный экран, пошаговый, по раундам.
Состояние боя — `GameState.combat` (один бой за раз), сохраняется вместе с игрой.

### Начало боя
- Событие «Один заражённый»: «Вступить в бой» → бой с 1 заражённым;
  «Попытаться избежать столкновения» → 70 % — обошли (+1 ход), 30 % — заметил,
  бой с 1 заражённым.
- Эффект события `combat` создаёт бой для этой экспедиции.
- DEV-команда `startCombat` (1–4 заражённых) — только для проверки; кнопка
  видна в интерфейсе лишь в dev-сборке или с `?dev` в адресе.
- В бою участвуют **живые** участники экспедиции (до 5).

### Позиции
- Две линии: **FRONT** и **BACK**, не больше 3 человек в каждой.
- При создании боя: участники по порядку списка группы — первые 3 в FRONT,
  остальные в BACK.
- До первого раунда (статус `setup`) линию можно менять свободно
  (`setCombatPosition`), в пределах 3/3.

### Раунд
1. Игрок выбирает действие каждому живому персонажу. Не выбравший —
   **DEFEND** по умолчанию.
2. «Подтвердить раунд»: действия игроков выполняются по порядку списка группы.
3. Если все заражённые мертвы — **победа** (заражённые не действуют).
4. Каждый живой заражённый атакует (см. ниже).
5. Если все персонажи мертвы — **поражение**.
6. Проверка подкрепления (шум).
7. Раунд +1, флаги DEFEND сбрасываются.

Вместо подтверждения можно **попытаться отступить** (всем отрядом).

### Действия
| Действие | Смысл |
|---|---|
| ATTACK | выбрать слот оружия (sidearm / primary / melee) и цель |
| DEFEND | не атакует; входящий урон −50 % до следующего раунда |
| MOVE | FRONT ↔ BACK (если в другой линии < 3), занимает действие |
| USE MEDICINE | −1 medicine экспедиции (supplies, затем haul); +30 health цели (себе или товарищу), не выше maxHealth |

- Ближнее оружие (категории `melee`, `tool`) — только из **FRONT**.
- Огнестрел — из FRONT и BACK; тратит `ammoPerAttack` ammunition экспедиции
  (supplies, затем haul). Нет патронов — стрелять нельзя
  (`NO_AMMUNITION`; если патроны кончились в том же раунде — выстрел не
  происходит, запись в лог).
- Если цель умерла раньше в этом раунде — атака переходит на первого живого
  заражённого.

### Попадание
```
навык = firearms (огнестрел) или melee (ближний бой)
hitChance = clamp(50 + 10 × навык, 20, 95) %
попадание: nextInt(1, 100) ≤ hitChance
```
Урон при попадании = `damage` оружия (без разброса). Пример: Герой (firearms 2)
с ПМ — 70 %; Максим (melee 3) с топором — 80 %.

### Заражённые
| Тип | health | attackDamage | accuracy | noise за атаку |
|---|---|---|---|---|
| Обычный заражённый | 70 | 18 | 75 % | 2 |

- Цель: случайный (`nextInt`) живой персонаж из **FRONT**; если FRONT пуст —
  из BACK.
- Попадание: `nextInt(1, 100) ≤ 75`.

### Броня и DEFEND
```
урон = floor(attackDamage × (100 − armor%) × (100 − defend%) / 10000)
armor%  = броня предмета в слоте body (куртка 5, бронежилет 25, нет — 0)
defend% = 50, если персонаж выбрал DEFEND в этом раунде, иначе 0
```
Пример: 18 → куртка 17, бронежилет 13, куртка + DEFEND 8, бронежилет + DEFEND 6.
Прочности нет.

### Шум и подкрепления
- `combatNoise` растёт на `noise` оружия за **каждую** атаку игрока (попал или
  нет) и на 2 за каждую атаку заражённого. Шум не спадает в течение боя.
- После каждого раунда (если бой продолжается) и если пришло меньше 3
  подкреплений:
  - шум ≥ 25 → шанс 50 %;
  - шум ≥ 15 → шанс 25 %;
  - бросок `nextInt(1, 100) ≤ шанс` → приходит 1 обычный заражённый.
- Максимум 3 подкрепления за бой. Шум **не** влияет на стратегическую карту.

### Отступление
```
шанс = clamp(50 + 10 × (живых персонажей − живых заражённых), 10, 90) %
успех: nextInt(1, 100) ≤ шанс
```
- Успех: бой окончен, экспедиция становится `aborted` и возвращается по
  обычному правилу (в конце следующего хода); найденное до боя сохраняется.
- Неудача: игроки теряют раунд — заражённые атакуют, затем подкрепления, раунд +1.

### Ранения и смерть
- Health 0–100 — общее с персонажем: раны остаются после боя.
- health ≤ 0 → персонаж **погиб** (`assignment = dead`): не действует, не ест,
  не возвращается на базу, не считается в лимите группы. Он убирается из
  участников экспедиции.
- Вся экипировка погибшего **сразу** снимается и переходит в
  `expedition.lostItems` (не на склад).
- **Победа:** выжившие забирают вещи павших по одной, если помещаются
  (`load + вес ≤ capacity`) — они переходят в `haulItems` и потом на склад.
  Не поместившееся остаётся в `lostItems` (запись в журнал).
- **Отступление:** вещи павших не подбирают.
- Когда экспедиция заканчивается (возвращение или гибель всего отряда), всё,
  что осталось в `lostItems`, переходит в `GameState.lostItems` —
  «потеряно в локации». На склад такие вещи не попадают.
- **Поражение (все погибли):** экспедиция заканчивается; припасы и найденные
  ресурсы пропадают; найденные предметы и снаряжение павших — в
  `GameState.lostItems`.

### Бой и экспедиция
- Пока в `GameState.combat` есть бой (идёт или показан итог), ход мира
  завершить нельзя (`COMBAT_ACTIVE`): экспедиция стоит, не возвращается,
  события не бросаются.
- Экипировку участников через базу менять нельзя (они не на базе).
- После победы экспедиция продолжает маршрут. Итог боя закрывается
  командой `closeCombat`.

## Порядок обработки хода (`endTurn`)

1. Если есть нерешённое событие — ход не завершается (ошибка `EVENT_PENDING`);
   если есть бой — тоже (`COMBAT_ACTIVE`).
2. Время +2 часа, счётчик ходов +1.
3. Если наступил новый день — суточный расход еды и воды: сначала база,
   затем каждая экспедиция по порядку отправления.
4. Экспедиции по порядку отправления: если пора — обыск локации; затем
   вернувшиеся — возвращаются (остаток supplies + haul + haulItems),
   остальные — бросок события.

## Случайность

- Вся случайность — только через `src/game/random` (mulberry32).
- Состояние RNG хранится в `GameState.rng` и сохраняется вместе с игрой:
  одинаковый seed + одинаковые команды = одинаковый результат.
- `Math.random()` в игровой логике запрещён (допускается только в UI для
  генерации seed новой игры).

## Подготовка: кнопки количества припасов

- food, water, medicine: `−1` / `+1`.
- ammunition: `−10`, `−1`, `+1`, `+10`, `MAX`.
- Любое изменение ограничено диапазоном `0 … запас базы`
  (`adjustSupplyAmount`).
- `MAX` = наибольшее количество, которое **и есть на складе, и помещается**
  в свободную грузоподъёмность выбранного отряда с учётом остальных
  припасов (`maxSupplyThatFits`); без выбранных участников — 0.

## Сохранение

- Ключ `localStorage`: `moscow-survival:save`. Текущая версия формата: **5**.
- v1 → v2: персонажам добавляются `hungry/thirsty = false`, экспедициям —
  пустой `haul`, `pendingEventId = null`, `seenEventIds = []`, `aborted = false`.
- v2 → v3:
  - экипировка `weapon/armor/backpack` (ID определений) превращается в
    экземпляры в реестре `items` с ID `<defId>-1` (при повторе — `-2`, …);
    слот нового формата: ПМ → `sidearm`, топор → `melee`, куртка → `body`,
    рюкзак → `backpack`; неизвестное оружие → `primary`, неизвестная броня → `body`;
  - добавляется пустой склад предметов `storage.items = []`;
  - экспедициям добавляются `supplies` = 0; отрицательные значения старого
    `haul` (в 0.2 они списывались при возвращении) сразу списываются с базы,
    в `haul` остаются только положительные;
  - старым записям журнала добавляются новые поля с пустыми значениями.
- v3 → v4: экспедициям добавляется пустой `haulItems = []`; записям журнала
  `lootFound` — `items = []`, `itemsLeftBehind = []`, `expeditionReturned` —
  `items = []`. Реестр предметов и ID не меняются. Активным экспедициям
  добавляется `searched = false`, `searchAt = returnsAt` (старые экспедиции
  обыскивают локацию при возвращении — как было в 0.3).
- v4 → v5: `combat = null`, `lostItems = []`, экспедициям — `lostItems = []`.
  Новые параметры оружия и брони — контент, в сейве не хранятся.
- Цепочка v1 → v2 → v3 → v4 → v5 сохраняется.
- Сейв, который не удаётся распознать или мигрировать, игнорируется —
  начинается новая игра (приложение не падает).
